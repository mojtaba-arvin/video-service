# GitHub Issue title convention

Use this format for every GitHub Issue title:

```text
<type>(<scope>): <short, clear description>
```

Allowed types are `feat`, `fix`, `docs`, `refactor`, `test`, `build`, `ci`, `chore`, `perf`, and `revert`.

The scope must be concise, lowercase kebab-case, and identify the affected domain or component. The description must be short and clear.

Do not put bracketed prefixes, priority codes, `Recover:`, or identity/run prefixes in the title. Keep priorities, milestones, feature or command IDs, agent identity, dates, and run metadata in labels or the Issue body.

When renaming an Issue, change only its title. Preserve its body, labels, milestone, assignees, comments, links, and other relationships.
